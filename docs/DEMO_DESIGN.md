# Demo presentation

The presentation uses a light, minimal visual language inspired by Apple's
software interfaces: one clear primary measurement, a quieter reference value,
consistent alignment, generous spacing, and restrained color. It is a recorded
analysis session, not a claim of live camera support.

## Research and choices

[Anthropic's analysis of generated frontend design](https://claude.com/resources/articles/improving-frontend-design-through-skills)
describes convergence on familiar default typography, colors, and layouts. These
are design tendencies rather than a reliable test of whether an interface was
generated by AI. The original demo's particular issues were its OpenCV lettering,
uniform emphasis, bright cyan/orange palette, crowded labels, and boxed panels.

Apple's [typography](https://developer.apple.com/design/human-interface-guidelines/typography),
[color](https://developer.apple.com/design/human-interface-guidelines/color), and
[layout guidance](https://developer.apple.com/design/tips/) inform the replacement:

- Use proper font rendering and a small number of type sizes and weights.
- Give the estimated heart rate primary emphasis and keep reference information secondary.
- Align related labels and measurements on shared margins.
- Use a neutral white/gray base, dark readable text, and a restrained red accent
  for the sampled skin and extracted pulse.
- Distinguish the reference using both gray color and dashed lines.
- Reserve rounded corners for the video and small session/time labels; avoid
  repeating identical cards or decorative gradients.

The renderer uses installed native sans-serif fonts with cross-platform
fallbacks. Linux builds use Nimbus Sans when available, a Helvetica-compatible
typeface. Apple font files are not bundled or redistributed.

## Measurement integrity

The redesign is implemented in `pulsetrace.demo_layout` and consumes the same
computed estimates, references, waveforms, and availability timestamps as the
previous renderer. No estimates are smoothed, replaced, delayed to hide errors,
or selected by the presentation layer. Missing values remain gaps.

The display labels the source as a recorded session and refers to completed
analysis windows. Before the first window completes, it shows the measuring
state. A rejected current window clears the previous estimate. The source video
and reference attribution are documented alongside the demo asset.

The renderer is 1440×900 at 15 presentation FPS. This is presentation encoding,
not an inference-throughput benchmark. The core estimator remains offline and
uses zero-phase filtering. A future camera application requires a separate
causal processing path and latency/accuracy evaluation.
